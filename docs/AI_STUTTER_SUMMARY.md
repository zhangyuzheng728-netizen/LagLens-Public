# AI 卡顿摘要：异常长帧总数与对齐口径（2026-11-15）

本次修复针对《赛博朋克 2077》诊断：本地诊断记录到 **12 次异常长帧，其中
10 次 ≥1 秒，最长约 3.54 秒**，旧 AI 解读只描述了一次停顿，容易让人以为
整段只卡过一次。修复在**摘要数据层**完成，并用同一份摘要服务快捷解读与后续
对话；提示词只补了一条计数要求。

## 1. 根因

- `build_report_summary` 已经统计了诊断事件数组，但只把
  `longest_display_stall` 写进事实表；事件总数和 ≥1 秒的计数没有进入
  `diagnosis.facts`，所以任何 AI 请求（一次性解读、聊天、追问）都只看到
  最长的一次。
- 事件窗口的“缺失信息”把所有事件都写成“位于采集开头”，而实际只有代表性
  窗口在开头；AI 会误以为所有长帧都集中在开头。
- 遥测存在但与帧时间无法可信对齐时，`_stall_evidence` 把“没有可对齐样本”
  说成“缺少 CPU/GPU 遥测”，与事实不符。
- 网关/公网探测超时没有明确写“不能归因给游戏服务器”。

## 2. 改了什么（数据优先）

| 位置 | 修改 |
|---|---|
| `ai_insight.build_report_summary` | 新增 `report["events"]`：`count`、`over_1s`、`longest_s`、`longest_at_s`、`first_at_s`、`last_at_s`，来自诊断事件数组；同时把 `telemetry_aligned` 传给硬件摘要与证据生成 |
| `diagnosis_pipeline.build_facts` | 新增事实 `abnormal_frame_events`（总数）与 `stalls_over_1s`（≥1 秒次数）；`longest_display_stall` 的 limit 明确“记录到的显示间隔，不一定是可见卡顿” |
| `ai_insight._stall_evidence` | `telemetry_aligned=False` 时不再取逐事件遥测，缺失项写“硬件遥测已采集，但帧时间基准未验证，无法与具体停顿对齐”；开头事件写“代表性事件位于采集开头（x 秒），该事件没有停顿前基线” |
| `ai_insight._build_evidence` / `_hardware_line` / `_quality_line` | 统一同一句对齐说明；明确“有采样、只是不能对齐”，不写成“没采到”，也不据此判断 CPU/GPU |
| `ai_insight.build_report_text` | 显示行增加“本次记录到 N 次异常长帧（其中 M 次 ≥1 秒），分布 X–Y 秒”；增加“异常长帧是采集记录，不等于玩家实际看到卡顿”；网络行增加“游戏服务器：未测”“网关/公网超时不能归因给游戏服务器” |
| `ai_insight.SYSTEM_PROMPT` | 一条：有异常长帧总数时先说总数和最长一次，不要只写一次停顿 |
| 4 KiB 预算 | 新增事实后，赛博朋克这份报告在 DeepSeek 的 4032 字节流式预算下会超限。按“先删可推导/重复事实、保留计数/最长/网络证据”的顺序收紧 compact 模式：仅在最紧的 compact=2 删除响应数、样本数、重复头部事实、GPU/CPU 中位之外的次要事实；多余标题不再重复发送。该报告最终 3992 字节 |

注意：compact=2 只影响“报告文字包裹”，**统计、停顿检测、导出数据和事实值
本身仍来自完整帧数据**；被删的只是已在头部/其他事实中可推导的条目。

## 3. 回归测试

`tests/test_ai_stutter_summary.py`（7 项，合成数据，未提交用户采集）：

1. 事实表保留 `abnormal_frame_events=12`、`stalls_over_1s=10`、最长 3.538 s；
2. 完整报告文字同时出现总数、≥1 秒次数和“不等于玩家实际看到”；
3. compact 聊天文字仍保留总数、最长事件和范围说明；
4. `telemetry_aligned=False` 时写“硬件遥测已采集…无法对齐”，不出现
   “缺少 CPU/GPU 遥测”，不输出硬件归因；
5. `telemetry_aligned=True` 时仍保留逐事件遥测窗口（不误伤已对齐场景）；
6. 网关/公网超时明确“游戏服务器未测”“不能归因给游戏服务器”；
7. 聊天 payload 与一次性摘要使用同一组事件事实。

完整测试：**751 passing**（原 744 + 7）。

## 4. 真实 DeepSeek 结果（源码版原生 GUI，2026-11-15）

用现有《赛博朋克 2077》采集（`Cyberpunk2077.exe_20261114_220035_600517.csv`）
发送同一句「全面分析」问题：

- 首段正文 0.813 s，完成 4.875 s，回复 792 字符，有 usage；
- 回复明确写出「12 次异常长帧，其中 10 次超过 1 秒，最长 3.5 秒，位于
  采集开始后约 4.3 秒」；
- 明确写“帧时间与硬件遥测的绝对时间基准未通过校验，不能直接归因到 CPU
  或 GPU”；
- 明确写“只探测网关/公网，没有测游戏服务器；超时不能据此说服务器有问题”；
- 没有再把所有事件说成“集中在采集开头”，改为提示最长一次可能和加载相关、
  需要带标注复测。

该结果**不是**打包版内点击验收；打包版的真机验收步骤见 STATUS 的待办。
